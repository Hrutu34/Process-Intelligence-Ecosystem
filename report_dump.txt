1. Why This Dataset Exists (and Why It’s Shaped This Way)

The original problem-idea owner is currently unavailable, so no curated data could be obtained in time. To keep the hackathon unblocked, we generated a realistic synthetic data kit that mirrors how BPMN work actually arrives in practice.

Unlike a typical dataset, this domain’s data is not tabular. The authentic inputs are (a) BPMN 2.0 XML files exported from modeling tools, and (b) free-text process descriptions written by employees. We therefore deliver both, rather than forcing process logic into spreadsheet rows.

Source-system assumption (one line)

BPMN 2.0 XML files as exported by modeling tools such as Camunda Modeler / bpmn.io / Signavio, paired with plain-language process descriptions typical of Word/SharePoint documentation. Everything is 100% synthetic — no real company, customer, or process data.

3.1 BPMN structure used

Each file is a standard BPMN 2.0 document. Teams will typically parse the following elements:

Element

XML tag

Meaning

Process / Collaboration

bpmn:process, bpmn:collaboration

The container; a collaboration adds a pool (participant).

Lane set

bpmn:laneSet / bpmn:lane

Roles owning each node (flowNodeRef links nodes to lanes).

Start / End event

bpmn:startEvent / bpmn:endEvent

Process trigger and outcome.

Task

bpmn:task / bpmn:userTask

A unit of work.

Exclusive gateway

bpmn:exclusiveGateway

XOR decision; may carry a default attribute.

Parallel gateway

bpmn:parallelGateway

AND split / join.

Sequence flow

bpmn:sequenceFlow

Ordered connection; may carry a conditionExpression.

Diagram interchange

bpmndi:BPMNShape / BPMNEdge

Visual coordinates so the model renders.

Fair-play note

Do not hardcode fixes to these exact IDs or names (e.g., “if task == Do needful”). Judges may run your solution against a modified copy of the corpus with renamed elements and additional planted defects. Detect by structure and semantics, not by literal string match.

6. How to Use the Kit

Unzip the corpus and load the .bpmn files with any BPMN 2.0 parser (or bpmn-js). Each file is valid XML with DI.

For the text-to-BPMN track, feed rows from the Description Bank sheet and emit BPMN 2.0 XML.

For the analysis track, produce two SEPARATE outputs per file: a plain-language description and a defect report.

Start with the clean references (F01, F02) to validate your parser, then move to the defective files.

You may extend the kit — add descriptions, author new BPMN files, or plant new defects — to stress-test your solution.

Reproducibility

The Excel catalog and the BPMN corpus are generated procedurally with a fixed random seed, so the kit is reproducible and easy to extend by following the same schema and defect patterns described above.
